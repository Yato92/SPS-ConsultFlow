# 2.8 Безопасность

## Меры защиты

### Аутентификация и авторизация

- OAuth 2.0 с выдачей JWT-токенов.
- Двухфакторная аутентификация (2FA) для административных ролей.
- Ролевая модель RBAC.
- Время жизни токена: 1 час для access, 30 дней для refresh.
- Блокировка учётной записи после 5 неудачных попыток входа.

### Защита данных

- Шифрование трафика: TLS 1.3.
- Шифрование данных в БД: AES-256.
- Хеширование паролей: bcrypt с солью.
- Маскирование персональных данных в логах.
- Шифрование резервных копий.

### Защита приложения

- Валидация и санитизация входных данных.
- Защита от SQL-инъекций (параметризованные запросы ORM).
- Защита от XSS (экранирование, CSP-заголовки).
- Защита от CSRF (токены, SameSite cookies).
- Ограничение частоты запросов (rate limiting).

### Инфраструктурная безопасность

- Изоляция сервисов в Kubernetes-неймспейсах.
- Сетевые политики (Network Policies).
- Регулярное обновление зависимостей и образов.
- Сканирование образов на уязвимости (Trivy).
- Секреты хранятся в Vault.

### Мониторинг и аудит

- Журнал всех действий пользователей (audit_log).
- Централизованный сбор логов (Loki).
- Алерты на подозрительную активность.
- Ежемесячный анализ инцидентов ИБ.

## Разграничение доступа по ролям

| Роль                  | Доступ к данным              | Действия                           |
| --------------------- | ---------------------------- | ---------------------------------- |
| Менеджер              | Заявки, клиенты, прайс-лист  | Создание заявок, расчёт стоимости  |
| Консультант           | Только свои заказы           | Просмотр, обновление статуса работ |
| Руководитель практики | Заказы своей практики        | Назначение консультантов           |
| Финансовый отдел      | Договоры, акты, счета        | Формирование, контроль оплат       |
| Юридический отдел     | Договоры                     | Проверка, согласование             |
| Руководство           | Аналитика, KPI, отчёты       | Просмотр без изменения данных      |
| Администратор         | Полный доступ                | Управление пользователями и ролями |
| Support               | Заявки, инциденты            | Обработка обращений                |
| Security Officer      | Журналы, аудит, инциденты ИБ | Расследование, реагирование        |

### Принципы разграничения доступа

1. **Минимальные привилегии** — каждый получает только необходимый доступ.
2. **Разделение обязанностей** — критичные операции требуют двух участников.
3. **Аудит всех действий** — любое изменение фиксируется в журнале.
4. **Регулярный пересмотр прав** — раз в квартал.

## Регуляторные требования

### 152-ФЗ «О персональных данных»

- Согласие субъекта на обработку ПДн.
- Хранение ПДн на территории РФ.
- Ограничение доступа к ПДн.
- Уведомление Роскомнадзора об обработке ПДн.
- Уничтожение ПДн по запросу субъекта.

### ГОСТ Р ИСО/МЭК 27001

- Управление рисками ИБ.
- Политика информационной безопасности.
- Управление инцидентами.
- Непрерывность бизнеса.
- Внутренние аудиты ИБ.

## Управление инцидентами ИБ

| Этап          | Действие                      | Ответственный    |
| ------------- | ----------------------------- | ---------------- |
| Обнаружение   | Мониторинг, алерты, обращения | DevOps / Support |
| Классификация | Оценка критичности            | Security Officer |
| Локализация   | Ограничение доступа, изоляция | DevOps           |
| Устранение    | Исправление, обновление       | Tech Lead        |
| Анализ        | Разбор причин, выводы         | Security Officer |
| Отчёт         | Документирование инцидента    | Security Officer |

**Целевые сроки:**

- Реакция на критичный инцидент — ≤ 30 минут.
- Локализация — ≤ 2 часов.
- Устранение — ≤ 24 часов.
