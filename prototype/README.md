# ConsultFlow — интерактивный UX/UI-прототип

Учебный макет на три экрана для РГР по дисциплине «Современные программные средства».
Показывает путь заявки и согласование документов без полноценной корпоративной системы.

## Как открыть

Прототип — один самодостаточный файл, сборка и сервер не нужны:

1. Откройте `prototype/index.html` двойным щелчком в браузере.
2. Или запустите локальный сервер из корня репозитория:

```bash
python -m http.server 8080 -d prototype
```

и откройте <http://127.0.0.1:8080>.

Макет рассчитан на desktop шириной 1440 px, но остаётся читаемым и на ноутбуке.

## Экраны

| Экран | Что показывает |
| --- | --- |
| **Заявки** | Реестр из четырёх демонстрационных заявок, поиск, фильтр по статусу, создание новой заявки. |
| **Карточка заявки** | Данные клиента, автоматическая обработка, уточнение требований, КП и документы, история. |
| **Кабинет клиента** | Подача заявки, статус, этапы, ответ на уточнение, согласование КП и подтверждение акта. |

Переключатель **«Сотрудник / Клиент»** в шапке меняет роль. Обе роли работают с одними
и теми же состояниями, поэтому действия клиента сразу видны сотруднику и наоборот.

## Демонстрационные данные

- Заявка №104, ООО «Вектор», Иван Петров.
- Услуга: консультация по оптимизации процесса продаж.
- Практика: управленческий консалтинг, консультант Анна Смирнова.
- Стоимость: 45 000 ₽, срок: 5 рабочих дней.
- SLA: ответ на обращение в течение 1 рабочего дня.
- Замечание клиента: «Добавьте обучение сотрудников в состав работ».

## Основной сценарий

1. Откройте заявку №104.
2. Проверьте данные, дубликаты, практику и консультанта.
3. Перейдите на вкладку «КП и документы», проверьте стоимость, срок и SLA.
4. Нажмите «Сформировать и отправить КП».
5. Переключитесь на роль «Клиент» и подпишите КП.
6. Вернитесь к сотруднику: сформируйте договор, начните работу, сформируйте акт.
7. В кабинете клиента подтвердите акт — заявка станет «Завершена».

## Альтернативный сценарий

1. Отправьте КП клиенту.
2. В роли клиента нажмите «Отправить замечания» и опишите изменения.
3. Вернитесь к сотруднику: замечания появятся над полями КП.
4. Исправьте предложение и нажмите «Отправить обновлённое КП» — появится версия 2.
5. Клиент снова видит две кнопки и подписывает новую версию.

## Ограничения прототипа

- Данные хранятся только в памяти страницы и исчезают после перезагрузки.
- Документы и подписи — имитация, скачивания файлов нет.
- Бэкенд, база данных и Telegram-бот не используются: это отдельный UX/UI-макет,
  а не замена рабочего приложения из `backend/`, `frontend/` и `bot/`.
- Согласования финансового и юридического отделов показаны статичными отметками
  внутри карточки заявки, без отдельных экранов.
