# ConsultFlow — интерактивный UX/UI-прототип

Учебный макет на три экрана для РГР по дисциплине «Современные программные средства».
Показывает путь заявки и согласование документов без полноценной корпоративной системы.

Прототип подключён к тому же FastAPI-бэкенду и базе данных, что и Telegram-бот с
React-дашбордом: заявки, статусы, документы и уведомления сохраняются в PostgreSQL
или SQLite и видны во всех трёх интерфейсах.

## Как открыть

Нужны запущенные backend и frontend. Из корня репозитория:

```bash
# 1. Backend (из папки backend)
cd backend
..\.venv-backend\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000

# 2. Frontend (из папки frontend, в отдельном терминале)
cd frontend
npm run dev
```

Откройте <http://127.0.0.1:5173/prototype/>.

При первом запуске backend создаёт демонстрационные данные, в том числе четыре
заявки №101–104 и клиента ООО «Вектор».

Через Docker:

```bash
docker compose up --build backend frontend
```

и откройте <http://127.0.0.1:8080/prototype/>.

Макет рассчитан на desktop шириной 1440 px, но остаётся читаемым и на ноутбуке.

## Экраны

| Экран | Что показывает |
| --- | --- |
| **Заявки** | Реестр заявок из БД: демо-заявки и, в режиме сотрудника, реальные VK/Telegram-заявки; поиск, фильтр по статусу, создание новой заявки, галочки для выбора и пакетное удаление. |
| **Карточка заявки** | Данные клиента, автоматическая обработка, уточнение требований, КП и документы, история. |
| **Кабинет клиента** | Подача заявки, статус, этапы, ответ на уточнение, согласование КП, тестовая оплата и подтверждение акта. |

Переключатель **«Сотрудник / Клиент»** в шапке меняет роль. В режиме сотрудника
подгружаются также заявки, созданные в VK-боте (ИИ и вручную), поэтому новая
заявка появляется в общем реестре. По такой заявке сотрудник может отправить
КП, договор и акт: клиент получит уведомление в VK с кнопкой заявки. В режиме
клиента остаётся только демонстрационная лента — чужие заявки не показываются.

Сотрудник может отметить несколько заявок галочками и нажать **«Удалить
выбранные»**. Из ленты они исчезают, но в базе данных остаются: включите
**«Показать удалённые»**, чтобы увидеть архив, и **«Вернуть выбранные»**, чтобы
вернуть заявки в работу.

## Основной сценарий

1. Откройте заявку №104.
2. Проверьте данные, дубликаты, практику и консультанта.
3. Перейдите на вкладку «КП и документы», проверьте стоимость, срок и SLA.
4. Нажмите «Сформировать и отправить КП».
5. Переключитесь на роль «Клиент» и подпишите КП.
6. Нажмите «Оплатить тестовой картой» — платёж имитируется, появляется чек.
7. Вернитесь к сотруднику: сформируйте договор, начните работу, сформируйте акт.
8. В кабинете клиента подтвердите акт — заявка станет «Завершена».

## Тестовая оплата

После подписания КП в кабинете клиента появляется блок «Оплата». Используйте
тестовую карту:

- номер: `4111 1111 1111 1111`;
- срок: любой будущий, например `12/40`;
- CVC: `123`.

Деньги не списываются, номер карты не сохраняется — в базе остаются только
сумма, последние 4 цифры и чек. Карта `4000 0000 0000 0002` имитирует отказ банка.
Повторная оплата уже оплаченной заявки возвращает ошибку.

## Альтернативный сценарий

1. Отправьте КП клиенту.
2. В роли клиента нажмите «Отправить замечания» и опишите изменения.
3. Вернитесь к сотруднику: замечания появятся над полями КП.
4. Исправьте предложение и нажмите «Отправить обновлённое КП» — появится версия 2.
5. Клиент снова видит две кнопки и подписывает новую версию.

## Связь с ботом и дашбордом

- Демо-клиент ООО «Вектор» привязан к Telegram ID `700000001` (Иван Петров).
  Заявка, созданная этим пользователем в боте, появляется в прототипе.
- Новая заявка из прототипа попадает в очередь менеджера в боте и в React-дашборд.
- Смена статуса или отправка КП из прототипа создаёт уведомление клиенту в боте.
- Менеджер `700000002` видит новые заявки и может менять их статусы через бота;
  изменения отражаются в прототипе.
- Документы (заявка, КП, договор, акт) формируются тем же сервисом
  `backend/app/services/documents.py`, что и в основном приложении.

## API прототипа

Все запросы идут на `/api/prototype`:

- `GET /bootstrap?order_id=...&include_external=true` — список заявок, текущая
  заявка, справочники; `include_external=true` добавляет VK/Telegram-заявки для
  режима сотрудника;
- `POST /orders` — создать заявку;
- `POST /orders/{id}/clarify`, `/answer` — уточнение и ответ клиента;
- `POST /orders/{id}/proposal`, `/sign`, `/remarks` — КП, подпись, замечания;
- `POST /orders/{id}/pay` — тестовая оплата картой и чек;
- `POST /orders/{id}/contract`, `/start`, `/act`, `/confirm-act` — исполнение;
- `POST /orders/{id}/practice` — практика и консультант.

Публичный демо-API включается флагом `PROTOTYPE_DEMO=true` и предназначен только
для учебного стенда.

## Ограничения прототипа

- Электронная подпись имитируется; скачивания PDF-файлов нет.
- Оплата тестовая: платёжный шлюз не подключён, реальные деньги не списываются.
- Загруженный файл сохраняется только как имя файла в карточке заявки.
- Согласования финансового и юридического отделов показаны статичными отметками
  внутри карточки заявки, без отдельных экранов.
- Демо-данные создаются один раз. Чтобы начать сценарий заново, удалите локальную
  SQLite-базу (например, `backend/consultflow.db`) и перезапустите backend.
