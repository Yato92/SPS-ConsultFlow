# VK-бот ConsultFlow

ВКонтакте-бот — второй канал ConsultFlow после Telegram. Он работает через
**Bots Long Poll API** сообщества: не нужен публичный HTTPS-адрес и вебхук.

## Что умеет

- `/start` — приветствие и меню;
- «Оставить заявку» — направление → описание → часы → сложность → подтверждение;
- «✨ AI-заявка» — свободный текст → извлечение данных, дубликаты, практика,
  команда, стоимость/SLA и черновик КП; заявка создаётся после подтверждения;
- «Мои заявки» — список заявок клиента со статусами и суммами; нажмите номер
  заявки, чтобы открыть карточку с действиями;
- карточка заявки в VK:
  - «📄 Прочитать документы» — текст КП, договора, акта и чека;
  - «💬 Ответить на уточнение» — ответ сотруднику;
  - «✅ Подписать КП» — согласование предложения;
  - «✍️ Замечания к КП» — отправка на доработку;
  - «💳 Тестовая оплата» — учебный платёж без списания денег;
  - «✅ Подтвердить работу» — приёмка акта и закрытие заявки;
- «Прайс-лист» — ставки и SLA;
- «Кабинет» — персональная ссылка в личный кабинет: клиент видит только свои
  заявки, статусы и документы;
- ИИ-консультант на Polza.ai: свободные вопросы, контекст своих заявок и тарифов;
- уведомления о новых заявках и смене статусов — с кнопкой «открыть заявку»;
- для менеджера: очередь заявок, смена статуса кнопками и ссылка на дашборд.

## Сценарий клиента в VK

1. Клиент оставляет обычную или AI-заявку — бот присылает номер и стоимость.
2. Сотрудник в дашборде или в VK-боте переводит заявку в «КП отправлено».
3. Клиенту приходит уведомление с кнопкой `📄 CF-2026-0001`.
4. Клиент открывает карточку, читает КП и нажимает «✅ Подписать КП» или
   «✍️ Замечания к КП».
5. После согласования клиент нажимает «💳 Тестовая оплата» — деньги не
   списываются, в карточке появляется чек.
6. Сотрудник переводит заявку в «В работе», затем в «Работа выполнена» —
   формируется акт.
7. Клиент нажимает «✅ Подтвердить работу» — заявка закрывается, акт подписан.

Все действия попадают в ту же базу, что и React-дашборд: сотрудник видит
изменения сразу, клиент — в VK и в личном кабинете на сайте.

## Настройка сообщества

1. Создайте сообщество ВКонтакте (публичная страница или группа).
2. Включите возможности ботов:
   **Управление → Сообщения → Настройки для бота → Возможности ботов → Включены**.
   Без этого VK отклоняет сообщения с клавиатурой (ошибка 912).
3. Включите сообщения сообщества:
   **Управление → Сообщения → Включить сообщения**.
4. Создайте токен:
   **Управление → Дополнительно → Работа с API → Создать ключ**.
   Дайте права **messages** и **manage** (для Long Poll).
5. Включите **Long Poll API** и событие **message_new**:
   **Управление → Дополнительно → Работа с API → Long Poll API**.
6. Узнайте ID сообщества:
   - из адреса `vk.com/club123456789` — это `123456789`;
   - или через `groups.getById`.
7. Добавьте в корневой `.env`:

```env
VK_GROUP_ID=123456789
VK_TOKEN=ваш-токен-сообщества
```

Токен сообщества — секрет. Не коммитьте `.env` и не публикуйте токен.

## Запуск

1. Backend уже должен работать:
   ```powershell
   start-consultflow.cmd
   ```
2. Запустите VK-бота:
   ```powershell
   start-vk-bot.cmd
   ```
   или вручную:
   ```powershell
   cd bot
   ..\.venv-backend\Scripts\python.exe -m vk_bot.main
   ```
3. В консоли должно появиться:
   ```text
   VK-бот запущен: сообщество 123456789, Long Poll готов
   ```
4. Напишите сообществу `/start`.

## Как бот хранит пользователей

VK не использует Telegram ID, поэтому бот создаёт в ConsultFlow технический ID
`-<VK_ID>`. Например, для VK ID `123456` это `-123456`. Отрицательный ID не
пересекается с положительными Telegram ID.

Поэтому в интерфейсе ConsultFlow такой клиент выглядит как пользователь с
отрицательным Telegram ID — это нормально для учебного прототипа.

## Менеджер ВКонтакте

Чтобы VK-пользователь получил роль менеджера:

1. Отправьте боту `/id` — он покажет VK ID, например `123456`.
2. В `.env` добавьте VK ID без минуса:
   ```env
   MANAGER_VK_IDS=123456
   ```
3. Перезапустите backend и VK-бота.

После этого в меню появятся «Очередь заявок» и «Дашборд». В очереди нажмите
номер заявки — откроется карточка с кнопками статусов: «✅ Квалифицировать»,
«📄 Отправить КП», «📑 Договор», «▶️ В работу», «🏁 Работа выполнена» и другими.
Для Telegram-бота менеджеры по-прежнему задаются через `MANAGER_TELEGRAM_IDS`.

## Защита от дублей

VK иногда повторяет событие `message_new` после переподключения Long Poll.
Бот запоминает ID сообщений и пропускает повторы. Кроме того, запустить два
экземпляра бота с одним токеном нельзя: второй процесс завершится с сообщением
«VK-бот уже запущен в другом окне». Это важно, потому что два Long Poll-клиента
одновременно получают одно сообщение и создают две одинаковые заявки.

## Уведомления

Фоновый цикл забирает уведомления из `/api/bot/notifications` и отправляет их
VK-пользователям с отрицательным `recipient`. HTML-теги из текста удаляются.
Если у уведомления есть `order_id`, бот добавляет кнопку `📄 <номер>`: она
открывает карточку заявки с документами и доступными действиями.

Telegram-бот пропускает отрицательные ID, а VK-бот — положительные, поэтому
оба бота могут работать одновременно на одной базе.

## Ограничения

- Оплата в VK — учебная: сумма фиксируется, деньги не списываются.
- VK-бот не поддерживает вложения и голосовые сообщения.
- История ИИ-диалога хранится в памяти процесса и очищается по `/start`.

## Ошибки

| Сообщение / лог | Причина |
| --- | --- |
| `VK не настроен` | не заданы `VK_TOKEN` и `VK_GROUP_ID` |
| `Access denied: token required` | пустой или неверный токен |
| `Long Poll не настроен` | не включён Long Poll API |
| `Access denied: group auth failed` | токен не от сообщества |
| `VK API вернул HTTP ...` | VK API недоступен |
| `Can't send messages for users without permission (901)` | пользователь не начинал диалог с сообществом; уведомление помечается `failed` и не повторяется |
| `Сервис ConsultFlow временно недоступен` | не запущен backend |
| `ИИ-сервис отклонил API-ключ` | проверьте `POLZA_API_KEY` |
