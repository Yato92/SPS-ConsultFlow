# Подключение базы данных reg.ru к ConsultFlow

ConsultFlow может хранить заявки, клиентов, документы и результаты ИИ в базе
reg.ru. Бот и сайт **не подключаются к базе напрямую**: они обращаются к backend
по API, а backend уже пишет всё в одну БД. Поэтому `DATABASE_URL` меняется только
у backend.

## 1. Сначала определите тип услуги

| Что у вас на reg.ru | Можно ли разместить проект | Что делать |
| --- | --- | --- |
| **VPS / VDS** с Ubuntu | Да | Docker Compose из [deploy-regru.md](deploy-regru.md) |
| **Виртуальный хостинг** (cPanel/ISPmanager/Plesk) | Нет: нет Docker и ASGI | Приложение — на VPS, база — на хостинге |
| **Облачная PostgreSQL** reg.cloud | Да | Подключить как внешнюю PostgreSQL |
| **MySQL на виртуальном хостинге** | Только как внешняя MySQL 5.7 | См. раздел 3 |

FastAPI нельзя нормально запустить на обычном виртуальном хостинге: там PHP,
Apache/nginx без управления процессом Python и без Docker. Залить `backend/` по FTP
недостаточно — нужен VPS или облачный сервис.

## 2. Вариант А: PostgreSQL на VPS (проще всего)

Если база будет на том же VPS, ничего подключать вручную не нужно:
`docker-compose.prod.yml` уже поднимает PostgreSQL в контейнере `db`.

```bash
docker compose -f docker-compose.prod.yml --profile vk up -d --build
```

Backend берёт `DATABASE_URL` по умолчанию:

```env
DATABASE_URL=postgresql+psycopg://consultflow:ПАРОЛЬ@db:5432/consultflow
```

Это самый устойчивый вариант для РГР: база не торчит в интернет, данные не
зависят от внешнего хостинга.

## 3. Вариант Б: MySQL 5.7 на виртуальном хостинге reg.ru

Виртуальный хостинг reg.ru даёт MySQL. Удалённый доступ включён **только для
MySQL 5.7**; для MySQL 8 удалённого доступа нет.

### 3.1 Создайте базу и пользователя

В панели хостинга → **Базы данных**:

1. Создайте базу, например `consultflow`, в кодировке **utf8mb4**.
2. Создайте пользователя и пароль.
3. Дайте пользователю доступ к базе.
4. Включите **Удалённый доступ** у пользователя.
5. В списке хостов укажите **IP вашего VPS**, а не `%`, если возможно.

Запишите:

```text
Host:     serverX.hosting.reg.ru
Port:     3306
Database: u1234567_consultflow
User:     u1234567_user
Password: ваш-пароль
```

Точные значения — в письме reg.ru или в панели. Префикс `u1234567_` — логин
услуги хостинга, он обязателен.

### 3.2 Пропишите DATABASE_URL

В `.env` на VPS:

```env
DATABASE_URL=mysql+pymysql://u1234567_user:ПАРОЛЬ@serverX.hosting.reg.ru:3306/u1234567_consultflow?charset=utf8mb4
```

Пароль нужно URL-кодировать:

| Символ | Код |
| --- | --- |
| `@` | `%40` |
| `:` | `%3A` |
| `/` | `%2F` |
| `#` | `%23` |
| `%` | `%25` |

Например, пароль `P@ss:w/rd` превращается в `P%40ss%3Aw%2Frd`.

### 3.3 Разрешите подключение

- В панели хостинга включён **Удалённый доступ**.
- В списке хостов — публичный IP VPS.
- Проверьте с VPS:

```bash
mysql -h serverX.hosting.reg.ru -P 3306 -u u1234567_user -p u1234567_consultflow
```

Если `mysql` не установлен:

```bash
sudo apt install -y default-mysql-client
```

Если соединение не открывается, пишите в поддержку reg.ru: порт 3306 с внешнего
IP может быть закрыт тарифом.

### 3.4 Запустите backend

```bash
cd /opt/SPS-ConsultFlow
docker compose -f docker-compose.prod.yml \
  -f docker-compose.external-db.yml --profile vk up -d --build
```

Проверка:

```bash
curl https://ваш-домен/health/db
```

Ожидаемо:

```json
{ "status": "ok", "dialect": "mysql" }
```

Если ответ `503`, смотрите `docker compose ... logs backend`: неверный пароль,
не включён удалённый доступ или IP не в списке.

### 3.5 Что будет с данными

- Заявки из VK/Telegram-бота, ИИ-разбор, КП, клиенты, документы и оплаты
  попадут в MySQL автоматически: все они пишутся через backend.
- Таблицы создаются при первом запуске backend.
- При `SEED_DEMO=true` на пустой базе появятся демо-заявки и администратор.
- Если в базе уже есть таблицы, seed не пересоздаёт их; проверьте, что вы
  подключаетесь к нужной базе.
- Локальная SQLite-база не переносится автоматически. Если нужны старые заявки,
  их надо отдельно экспортировать и импортировать.

## 4. Вариант В: PostgreSQL на втором сервере

Если PostgreSQL стоит на отдельном VPS:

1. Создайте базу и пользователя.
2. Разрешите подключение только с IP app-сервера в `pg_hba.conf`.
3. Откройте порт 5432 только для этого IP (ufw / firewall reg.ru).
4. В `.env`:

```env
DATABASE_URL=postgresql+psycopg://consultflow:ПАРОЛЬ@IP_БД:5432/consultflow
```

5. Проверьте:

```bash
psql "postgresql://consultflow:ПАРОЛЬ@IP_БД:5432/consultflow" -c "select 1;"
```

Не открывайте PostgreSQL в интернет для всех (`0.0.0.0/0`).

## 5. Если база уже на reg.ru, но приложение ещё локально

Можно проверить подключение с локального компьютера:

```powershell
$env:DATABASE_URL="mysql+pymysql://u1234567_user:ПАРОЛЬ@serverX.hosting.reg.ru:3306/u1234567_consultflow?charset=utf8mb4"
cd backend
..\.venv-backend\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000/health/db>. Если `dialect: mysql`, backend видит
базу. После этого можно переносить проект на VPS, не меняя `DATABASE_URL`.

## 6. Ограничения и важные нюансы

- **MySQL 8**: удалённый доступ на виртуальном хостинге reg.ru не поддерживается.
  Для MySQL 8 нужен VPS/облако.
- **MSSQL**: проект не поддерживает MSSQL без отдельного драйвера и адаптации.
- **SQLite** подходит только для локальной демонстрации; для нескольких
  пользователей и бота лучше PostgreSQL/MySQL.
- **Права пользователя БД**: достаточно `SELECT, INSERT, UPDATE, DELETE, CREATE,
  ALTER, INDEX` на одну базу. Не используйте root.
- **Резервные копии**: `mysqldump` для MySQL или `pg_dump` для PostgreSQL.
- **Секреты**: `.env` с паролем БД не коммитьте; на сервере `chmod 600 .env`.

## 7. Если нужна помощь с подключением

Нужны только несекретные параметры:

1. Это VPS или виртуальный хостинг?
2. Тип БД: MySQL 5.7, MySQL 8, PostgreSQL?
3. Домен проекта.
4. Host/port/имя базы/пользователь (пароль — только в `.env` на сервере).

Пароль и SSH-ключ не отправляйте в чат. Для подключения базы достаточно
временного SSH-доступа или выполнения команд на сервере.
